# SPECIFICATION — MVP бота записи «Хиджама №1»

Технический чертёж для реализации без догадок. Стек: **Node.js**, **Telegraf**, **Supabase (PostgreSQL)**, **ЮKassa**, хостинг **Amvera**.

---

## 1. Модули MVP

| Модуль | Назначение |
|--------|------------|
| `bot-telegram` | Диалоги, меню, выбор слота, ссылки на оплату, статусы. |
| `api-http` | Webhook ЮKassa, health (REST для админки **не используется** — админка только в Telegram). |
| `payments-yookassa` | Создание платежа 500 ₽, обработка `payment.succeeded`. |
| `db-supabase` | Схема, миграции, RLS, доступ из сервиса через `service_role` / anon по политикам. |
| `notifications` | Сообщения мастеру; напоминания клиенту и мастеру. |
| `scheduler` | Планировка напоминаний (−120 мин, −60 мин от `starts_at`). |
| `admin` | Управление слотами и перенос/отмена записей (только мастер). |

## 2. User stories (клиент)

1. **US-C1.** Как клиент, я хочу нажать Start и получить приветствие с кратким описанием клиники и кнопкой «Записаться», чтобы понять, куда попал.
2. **US-C2.** Как клиент, я хочу видеть список **свободных** слотов на ближайшие дни, чтобы выбрать время.
3. **US-C3.** Как клиент, после выбора слота я хочу указать **имя** и **телефон** (и при необходимости комментарий), чтобы мастер мог связаться.
4. **US-C4.** Как клиент, я хочу увидеть **диапазон полной стоимости** (3500–6000 ₽) и сумму **предоплаты 500 ₽**, затем перейти к оплате ЮKassa.
5. **US-C5.** Как клиент, после оплаты я возвращаюсь **в чат с ботом** (из формы ЮKassa по `return_url`), а **подтверждение оплаты и записи** получаю **сообщением от бота** в этом чате (текст с датой/временем сеанса и суммой предоплаты). Источник истины — успешный webhook `payment.succeeded`; сообщение в Telegram отправляется сразу после фиксации оплаты в БД.
6. **US-C6.** Как клиент, я хочу получить **напоминания за 2 часа и за 1 час** до сеанса в этот же чат с ботом.

**Edge cases (клиент):**

- Слот заняли между просмотром и оплатой → бот сообщает, предлагает другие слоты; платёж не завершён или возврат по политике (отдельное бизнес-правило: при отмене платежа запись не создаётся).
- Платёж просрочен (timeout ЮKassa) → запись в статусе `pending_payment` может быть освобождена планировщиком после TTL (например 15–30 мин).
- Повторный заход: если у пользователя уже есть активная запись, показать её и кнопку «Связаться» / не дублировать без подтверждения.

## 3. User stories (мастер)

1. **US-O1.** Как мастер, я хочу получать **мгновенное уведомление в личный Telegram** о новой оплаченной записи (имя, телефон, время, сумма предоплаты).
2. **US-O2.** Как мастер, я хочу **создавать/закрывать слоты** в расписании через админку.
3. **US-O3.** Как мастер, я хочу **отменить или перенести** запись, чтобы слот освободился или изменился; клиенту уходит уведомление (если технически возможно через бота).

**Edge cases (мастер):**

- Неверный `ADMIN_TELEGRAM_ID` → уведомления не уходят; логирование ошибки.
- Отмена менее чем за X часов — политика возврата предоплаты **вне MVP кода** (можно зафиксировать текстом в оферте); в системе статус `cancelled_by_admin`.

## 5. RLS (Supabase)

**Принцип MVP:** прямых запросов к БД из клиента (браузера) **нет**; бот и сервер используют **service role** или выделенный backend. Тогда:

- Включить RLS на всех таблицах.
- Политика по умолчанию: **нет доступа** для `anon` / `authenticated` с клиента Supabase.
- Опционально позже: отдельная веб-админка на Supabase Auth + политики для роли `admin` (сейчас админка только в Telegram, приложение ходит в БД с service role).

Таким образом, утечки через PostgREST исключены, пока нет публичного frontend на anon-ключе.

## 6. API (HTTP)

Все маршруты — **HTTPS** на Amvera. Формат JSON, кроме webhook (как требует ЮKassa).

### 6.1 `GET /health`

**Ответ 200:** `{ "ok": true }`  
Для пробы Amvera / балансировщика.

### 6.2 `POST /webhooks/yookassa`

- **Заголовки:** проверка **IP** (список ЮKassa) и/или **секретного ключа** webhook из ЛК ЮKassa (Authorization Basic user:password), как в актуальной документации ЮKassa.
- **Тело:** объект уведомления (например `event` = `payment.succeeded`).
- **Логика:**
  1. Проверить дедупликацию по `yookassa_event_id` в `payment_events`.
  2. Найти `appointment` по `metadata.appointment_id` или по `yookassa_payment_id`.
  3. При `payment.succeeded`: `appointments.status = confirmed`, `slots.is_booked = true`, **отправить клиенту в Telegram** сообщение с подтверждением оплаты и записи; **уведомить мастера** в личку.
- **Ответ:** 200 после успешной обработки; 4xx при неверной авторизации; 5xx только при временных ошибках (с retry со стороны ЮKassa).

**Коды ошибок (внутренние логи):**

| Ситуация | HTTP |
|----------|------|
| Неверная подпись / auth | 401 |
| Дубликат события | 200 (идемпотентно) |
| Платёж не найден | 200 или 404 — зафиксировать в спецификации реализации: предпочтительно 200 после логирования, чтобы не зациклить retry |

## 7. Интеграция ЮKassa

- **Сумма:** 500 ₽ (фикс для MVP).
- **metadata:** `appointment_id`, `telegram_user_id` (для логов и связки с чатом).
- **return_url (зафиксировано):** ссылка **в чат с ботом** — `https://t.me/<BOT_USERNAME>` (без отдельной лендинг-страницы «оплата принята»). После редиректа клиент снова в Telegram; **текст подтверждения оплаты не на странице ЮKassa**, а **в сообщении бота** после обработки webhook (см. US-C5). Если webhook задержался, в чате допустимо короткое ожидание; опционально при `/start` или повторном входе показывать статус «ожидаем оплату» / «запись подтверждена» по данным БД.
- **Тестовый магазин** до продакшена.

Переменная окружения: `BOT_USERNAME` (без `@`) для сборки `return_url`, если не зашито в конфиг.

## 8. Telegram (Telegraf)

- **Команды:** `/start`, `/help`, опционально `/mybooking`.
- **Сценарий:** машина состояний или сцены: приветствие → список слотов (inline-кнопки с `callback_data` с id слота) → контакт → создание `appointment` + `pending_payment` → создание платежа ЮKassa → ссылка на оплату → клиент оплачивает → `return_url` ведёт в **t.me/бот** → webhook подтверждает оплату → **бот пишет в тот же чат** подтверждение записи.
- **Тексты:** русский, тёплый нейтрально-уважительный тон, без медицинских обещаний; упоминание полной стоимости диапазоном.
- **Переменные окружения:** `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `WEBHOOK_URL` или long polling (на Amvera предпочтительно webhook с публичным URL).

## 9. Планировщик напоминаний

- Запуск каждые **1–5 минут** (cron в процессе или внешний триггер Amvera).
- Выборка: `appointments.status = confirmed`, `slots.starts_at` в окнах [now+115m, now+125m] для 2ч и [now+55m, now+65m] для 1ч, с проверкой `reminder_*_sent_at is null`.
- После отправки — проставить `reminder_2h_sent_at` / `reminder_1h_sent_at`.
- Дубли не отправлять.

## 10. Админка (MVP) — **только Telegram**

Доступ: любое действие админа разрешено **только** если `ctx.from.id === ADMIN_TELEGRAM_ID` (число из env). Иначе — игнор или вежливый отказ «команда недоступна».

**Веб-админка, отдельное REST API для админки и HTML-формы — вне скоупа MVP.**

**Минимальный набор команд/шагов (черновик, можно объединить в меню-кнопки):**

| Действие | Поведение |
|----------|-----------|
| Список ближайших слотов | Показать опубликованные слоты с пометкой свободен/занят. |
| Добавить слот | Диалог или командные аргументы: дата, время начала, длительность (например 60 мин) → запись в `slots`. |
| Снять с публикации / удалить слот | Только если слот не занят подтверждённой записью (или с предупреждением). |
| Список записей | Подтверждённые записи на период. |
| Отменить запись | Статус `cancelled`, `slots.is_booked = false`; **уведомление клиенту** в чат с ботом (текст о переносе/отмене). |
| Перенос записи | Назначить другой свободный `slot_id`, уведомить клиента. |

Все ответы админу — в том же чате с ботом (личные сообщения боту).

## 13. Критерии готовности MVP

- [x] Клиент проходит путь от `/start` до подтверждения после тестовой оплаты.
- [x] Webhook ЮKassa идемпотентен, слот не двойнится.
- [x] Мастер получает уведомление о новой записи.
- [x] Два напоминания уходят в согласованное время (проверка на тестовом слоте).
- [x] Мастер может создать слот и отменить запись **только через Telegram-админку** (`ADMIN_TELEGRAM_ID`).
- [x] `.env.example` без секретов; README с шагами деплоя Amvera.

**Дальше (после MVP):** тексты приветствия из `settings.welcome_text` (редактирование в Supabase); v2 — см. `PROJECT_IDEA.md` (MAX, история, отзывы).
